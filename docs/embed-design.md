# 本地向量偏好记忆（P5 · 执行书与实测）

> **状态：第一版已落地（默认关闭）。** 本文是它的执行书 + 实测记录，
> 与 `docs/p5-vector-feasibility.md`（可行性研究）配套：
> 那份回答"**能不能做**"，这份回答"**做成了什么、量到多少**"。
>
> 相关决策：**D7**（AI 只做偏好重排）、**D19**（频率 → 上下文 → 向量）、
> **D46**（默认关闭的可选能力可以突破 30 MB 红线，但必须默认关 + 上限进文档与称重台
> + 红线本身不动）、**D13**（影响排序的量一律定点）、**D38**（不确定性注入——
> 这里连随机都不需要）。

## 0. 一句话

**不上网、不加载模型、不引入依赖**：把用户**本地历史**里的
`(上下文词 → 下一个词)` 计数**投影**成一组 `i16` 整数向量，
在 `Lane::Input` 的重排链上加一个有界的偏好分。

```bash
cargo run -p stele-cli --release -- --scheme-dir schemes/stele-default \
    --userdb /tmp/u.mem --embed --candidates=4 tianqi
```

**默认关闭**（D46 第①条）：不给 `--embed` 时它完全不参与，默认行为逐字节可复现。

---

## 1. 它填的是哪个空

三条已有的路各缺一块，而**合起来正好漏掉一个位置**：

| 已有 | 它回答 | 缺什么 |
| --- | --- | --- |
| 词库权重 | 这个词**全局**多常用 | 不看上下文 |
| **P4a** `MemoryRanker` | 这个**编码**打过哪个词 | **不看上下文** |
| **P4b** 预测表 | 这段**上下文**之后常接什么 | 只喂 `Lane::Predict`，**不碰 `Lane::Input`** |

于是"**同一个编码下的几个同音词，按上文该选哪个**"没有任何一档在管。
实例：敲 `tianqi` 时 `天气` 与 `田七` 谁在前——P4a 只看历史次数，
分不清上文是「今天」还是「农田」。

## 2. 算法（足够小，可以整段讲完）

记 `M[c][w]` = "`c` 之后出现过 `w`"的计数（**就是 P4b 那张预测表**）。
不存 `M`（那是 V×V），而是给每个词一条**确定的 ±1 投影** `r_x`：

```text
v_w = Σ_c  M[c][w] · r_c          （只存这一张：V × dim 个 i16）
s   = Σ_{c∈上下文} r_c            （查询时现算）
score(上下文, w) = dot(s, v_w)
             ≈ dim · Σ_{c∈上下文} M[c][w]      （因为 r_c · r_{c'} ≈ dim·δ）
```

**它估的就是"这个词跟着这段上下文出现过多少次"**——只是用一条定长向量
把它装下来了。

### 2.1 三条让它可复现的约束

| 约束 | 做法 |
| --- | --- |
| **没有随机** | 投影由**词的哈希**决定（`projection::signs`，splitmix64 扩散）。同一份历史 ⇒ 同一批向量，跨进程跨平台 |
| **没有浮点** | 投影是 ±1、累加是 `i32` 饱和加、量化是整数除法与舍入。**唯一的除法在装载期** |
| **没有迭代** | 一次投影 + 一次量化。没有梯度、没有学习率、没有负采样——**换来可复现与可解释，代价是表达能力弱** |

### 2.2 重排器的三条保守选择

1. **只给"不是猜的"候选加分**。于是"重排器把猜测顶到精确之前"在**算术上**
   不可能发生——铁律不是靠事后检查守住的，而是靠不做那件事。
2. **按名次加分，不按分值**。分值量纲取决于词频与维数，按分值缩放需要一个
   "信号够不够强"的阈值，而那个阈值没有数据可依据。名次法**没有可调常数**：
   第 1 名拿满额，第 2、3 名递减。
3. **只加有界的量**：默认 **前 3 名、每次最多 4000 毫对数**（≈ 权重 55 倍），
   靠内核的 `clamp_bonus` 落笔。它只打破旗鼓相当的僵局，不压过词库权重。

## 3. 验收：对比集 + A/B 对照

对比集：**`tools/embed/context-cases.tsv`**（`docs/HANDOFF.md` §7.7 的那条纪律——
**先有表，再写代码**）。它的形状是：

- `history` 行：用户"打过"的句子（同时喂 P4a 与预测表，**向量就是从后者学的**）；
- `case` 行：上文 + 待输入编码 + 期望词。

**刻意把期望词的 P4a 次数压得比对手低**，于是基线必然选错——
上下文成了唯一的判别依据。向量若没学到上下文，它同样会选错。

### 3.1 实测（`cargo test -p stele-embed --test context_cases -- --nocapture`）

| 用例 | 基线（权重 + P4a） | 加上向量 |
| --- | --- | --- |
| 上文「今天」→ `tianqi` → **天气** | **第 2 位**（错） | **第 1 位** ✅ |
| 上文「明天」→ `tianqi` → **天气** | **第 2 位**（错） | **第 1 位** ✅ |
| 上文「农田」→ `tianqi` → **田七** | 第 1 位 | 第 1 位 ✅（**无回归**） |

两条断言一起守：**改善**（基线错的被修好）与**无净损失**（基线对的仍对）。
只有前者的话，一个"随机打乱候选"的实现也能碰巧过。

> **这是"它有用"的第一个证据，但它很小**：3 条用例、一个自造的用户历史。
> 它证明的是**机制成立**，不是"在真实打字上一定更好"。
> 真实收益仍需一份更大的、由所有者手写的对比集——见 §6。

## 4. 内存账（D46 第②条：上限进文档 **并** 进称重台）

向量表 = `词表大小 V × 维数 dim × 2 字节`。默认 `dim = 32`，词表来自
用户记忆的预测表（受 `DEFAULT_PREDICT_CAPACITY` 约束）。

| 规模 | 常驻（式样） | 来源 |
| --- | --- | --- |
| 5 000 词 | **0.3 MiB** | 轻度用户 |
| **40 000 词（实测）** | **2.44 MiB** | `stele-bench … --embed` 打印的 `2500 KiB` |
| 50 000 词（上界） | 3.05 MiB | 外推（预测表到不了这个规模） |

**装载峰值另算**：训练时还有一块 `V × dim × 4 字节` 的 `i32` 累加缓冲
（4 万词 = **5.1 MiB**）与调用方给的样本快照（约 3 MiB）。
它们在训练结束就释放，但**分配器往往留住页面**（RSS 只涨不落）——
所以称重台上看到的增量是 **约 +9 MiB**，而稳态只有 2.44 MiB。
这与 HANDOFF §5 第 44 条是同一类"尺子"问题，只是方向相反。

### 4.1 按键延迟（实测，真实词库 + 3 万输入记忆 + 2 万预测历史）

| | P50 | P95 | P99 |
| --- | --- | --- | --- |
| 不带 `--embed` | 50.41 µs | 96.27 µs | 108.52 µs |
| **带 `--embed`** | **48.84 µs** | **92.72 µs** | **106.06 µs** |

**差别落在噪声里**：每键只做一次 `dim=32` 的整数点积（与
`tools/embed-probe dot 200 64` 量到的 2 µs 同量级，且只在有上下文时才跑）。

### 4.2 与 D46 的关系

**它小到不需要动用 D46 的例外**：默认关闭时它占 0；开启时稳态 +2.44 MiB，
总常驻约 32 MiB（实测）——**越过 30 MB 红线**，因此按 D46 记账：
默认关 ✅、上限写进本文与称重台 ✅、红线对默认配置不动 ✅。

## 5. 第一版**不**做什么（诚实清单）

| 不做 | 为什么 | 影响 |
| --- | --- | --- |
| **两步共现**（`M²`） | 直接项与两步项的量纲差几个数量级，配平需要一个没有数据依据的常数 | 目前只在"上下文**词**见过"时生效；**没有**跨词的语义泛化 |
| **子词回退**（按字拆） | 见不到过的**上下文词**就是没有向量。"编一个"会让功能看起来像做了、其实在猜——本项目最恨的形状 | 新词没有向量 |
| **在线更新** | 向量在装载时从预测表一次性学出；学习本身仍由 P4a/P4b 负责 | 运行中新增的历史要等下次启动才进向量 |
| **独立持久化** | 向量是**派生状态**：从预测表算得出来，就不必再存一份、也不必处理"两个文件不同步" | 每次启动重训（4 万词约几十毫秒） |
| **`Lane::Predict`** | 那条通道由 P4b 的 `predict_next` 供应，不是重排 | 预测候选不受向量影响 |

**最重要的一条**：**不要把"一点点哈希平滑"说成"理解了语义"。**
它现在学的是"这段上文之后出现过什么"，不是词义。

## 6. 下一步（按价值排序）

1. **把对比集做大**（**需要所有者出手**）：现在只有 3 条、还是我造的。
   §3 的结论只能证明机制；要回答"值不值得默认开"，需要一份**手写**的、
   覆盖真实打字习惯的用例集（照 `tools/predict/collocations.tsv` 的形状）。
   **注意**：不能用真实按键日志（与隐私承诺冲突），也不能用合成历史"做局"。
2. **两步共现**：给"没见过的搭配"一点泛化。要先解决量纲配平
   （建议：把两步项按 `1/Σ_w M[c][w]` 归一之后再与直接项相加，并**用对比集量**）。
3. **子词回退**：让"没见过的上下文词"也有向量（按字投影）。
   这一步才会让向量带来**跨词**的泛化。
4. **只在对比集显示收益之后**，才考虑是否要把它从"默认关"变成"默认开"。

    --userdb /tmp/e.mem --seed-memory=30000

    --userdb /tmp/e.mem --seed-predict=20000
cargo run -p stele-bench --release -- --scheme-dir schemes/stele-default --schema=pinyin \
    --userdb /tmp/e.mem --embed          # 报告里会打出向量表的大小与加成上限
