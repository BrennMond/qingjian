# tools/embed-probe — P5 的内存预算探针

**它回答的是 P5 的门槛问题，不是 P5 本身。** 结论写在
[`docs/p5-vector-feasibility.md`](../../docs/p5-vector-feasibility.md)。

它**不训练、不加载、不量化**任何模型——因为"用哪份数据、什么许可"
正是评审要**先**回答的问题（PLAN §10），不是探针能替它回答的。
它只回答两件可测的事：

1. **一张向量表要占多少内存**（`V × D × bytes` 的名义值 vs 实测 RSS）；
2. **一次重排要花多少时间**（200 候选 × D 维 int8 点积）。

## 用法

```bash
BIN="cargo run --release --manifest-path tools/embed-probe/Cargo.toml --"

# 表内存：全词库 414 525 条、64 维、int8（每分量 1 字节）
$BIN table 414525 64 1

# 表内存：常用词 50 000 条、64 维、int8
$BIN table 50000 64 1

# 点积：200 个候选 × 64 维，跑 20 万轮
$BIN dot 200 64 200000

# 乘积量化：414 525 条、8 段（每条 8 字节码）
$BIN pq 414525 8
```

## 三条读法（避免误用）

- **`table` 的 RSS 增量 ≈ 名义值（比值 1.00）**，所以这个项目的算术
  可以直接用 `V × D × bytes`，不必再留分配器余量。
- **它量的是"常驻表"**。真实设计里向量表可以是**文件背书 + 按需 `read_at`**
  （照 `qingjian-table`），那时表**不进进程 RSS**——见报告的 §2.3。
- **`dot` 是标量循环，没有 SIMD**。这是"我们会写的那种循环"，
  所以它是保守估计，不是乐观估计。
